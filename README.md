# Dead Stock Ledger — คู่มือติดตั้งและทดสอบ

## แก้ไขล่าสุด (28 ส.ค. 2569 — รอบที่ 3)

5. **กราฟ "มูลค่าสินค้าที่ลงขายรายเดือน (บาท) — Facebook vs Shopee" นับมูลค่าผิดวิธี** — เดิมคำนวณ
   มูลค่าจาก ราคาขาย/หน่วย × 1 (นับครั้งเดียว) ที่เดือนซึ่งแยกได้จากข้อความในคอลัมน์ "ช่องทางการลงขาย
   1/2" (เช่น "ลงขาย FB 03-03-69" → นับเป็นมูลค่าที่เดือน มี.ค.) ทั้งที่เดือนที่ลงขายไม่ใช่เดือนที่ขายได้จริง
   แก้เป็น: ใช้คอลัมน์ "ช่องทางการลงขาย 1/2" เพื่อ**ระบุว่าสินค้าตัวนั้นลงขายช่องไหน** (FB และ/หรือ
   Shopee) เท่านั้น ส่วน**มูลค่า**ให้คำนวณจากจำนวนที่ขายได้จริงในแต่ละเดือน — คือคอลัมน์เดือน
   (ม.ค.–ธ.ค.) ใต้หัวข้อ **"จำนวนที่โอนออกแยกตามเดือน 2026"** ในชีตหลัก (คอลัมน์เดียวกับที่ใช้ทำกราฟ
   ยอดเคลื่อนไหว) × ราคาขาย/หน่วย นับเฉพาะเดือนที่มีจำนวนโอนออกมากกว่า 0 (qty > 0)
   - ถ้าสินค้าลงขายทั้ง Facebook และ Shopee พร้อมกัน มูลค่าจะถูกนับซ้ำในทั้งสองช่องทาง เพราะชีต
     ไม่ได้เก็บยอดขายแยกตามช่องทางไว้ต่างหาก (มีคอลัมน์เดือนชุดเดียวใช้ร่วมกัน)
   - กราฟ "แนวโน้มการลงขายรายเดือน — Facebook vs Shopee" (นับจำนวนรายการที่ลงขาย ไม่ใช่มูลค่า)
     ยังคงอ้างอิงเดือนจากวันที่ในข้อความคอลัมน์ช่องทางการลงขายเหมือนเดิม ไม่ได้แก้ในรอบนี้

## แก้ไขล่าสุด (28 ส.ค. 2569 — รอบที่ 2)

4. **แนวโน้มรายเดือน (ทั้ง 4 กราฟ) และประวัติการเคลื่อนไหว/ลงขาย ให้อ้างอิงแท็บ `ENGSPTอะไหล่ไหม่` โดยตรง**
   — ยกเลิกการอ้างอิงแท็บ `MovementLog`/`ListingLog` ทั้งหมด (แท็บเหล่านี้ไม่ได้ถูก AppSheet
   เขียนข้อมูลจริง จึงทำให้กราฟและประวัติว่างเปล่า) เปลี่ยนเป็น:
   - **กราฟยอดเคลื่อนไหว/มูลค่าเคลื่อนไหวรายเดือน** — รวมยอดจากคอลัมน์เดือน (ม.ค.–ธ.ค.)
     ของสินค้าแต่ละตัวในชีตหลักโดยตรง
   - **ประวัติการเคลื่อนไหว** — สร้างจากคอลัมน์เดือนของสินค้าแต่ละตัว (เดือนไหนมียอดไม่เป็น 0
     จะแสดงเป็น 1 รายการ) เนื่องจากชีตหลักเก็บเป็นยอดรวมต่อเดือน ไม่มีเวลาบันทึกที่แท้จริง
     รายการจึงไม่มีเวลา ("-") แต่มีป้ายกำกับเดือนแทน
   - **ประวัติการลงขาย** — สร้างจากคอลัมน์ "ช่องทางการลงขาย 1" (FB) และ "ช่องทางการลงขาย 2"
     (Shopee) โดยแยกวันที่ออกจากข้อความ เช่น "ลงขาย FB 03-03-69" → ช่องทาง Facebook,
     วันที่ 03-03-69 (ไม่มียอดขายเป็นตัวเลข เพราะคอลัมน์นี้เก็บแค่วันที่ลงขาย ไม่ใช่ยอดขาย)

## แก้ไขล่าสุด (28 ส.ค. 2569 — รอบที่ 1)

1. **กราฟ "ยอดเคลื่อนไหวรายเดือน" ไม่ขึ้น** — สาเหตุคือกราฟเดิมอ่านค่าจากคอลัมน์เดือน (F–Q)
   ในชีตหลัก ซึ่งปัจจุบันไม่มีใครอัปเดตค่าแล้ว (การเคลื่อนไหวจริงถูกบันทึกไปที่แท็บ
   `MovementLog` โดย AppSheet ต่างหาก) แก้โดยให้กราฟดึงข้อมูลจาก `MovementLog` แทน
2. **"มูลค่าคงเหลือรวม" ไม่ขึ้นยอด / คงเหลือไม่ตรง** — หน้าเว็บเดิมคำนวณ "คงเหลือ" เองจาก
   คงค้างเริ่มต้น − ยอดเดือน (ซึ่งเดือนว่างเปล่า) แทนที่จะใช้ค่าจากคอลัมน์ "คงเหลือ" ที่ AppSheet
   ดูแลอยู่จริง แก้โดยให้เว็บใช้ค่าคอลัมน์ "คงเหลือ" ตรงๆ
3. **"ลงขายแล้วบน Facebook/Shopee" ดึงข้อมูลผิดคอลัมน์** และ **ราคาไม่ขึ้น** — `Code.gs`
   เดิมอ้างอิงคอลัมน์ตามตำแหน่งตายตัว (S/T/U) ซึ่งจะพังทันทีถ้ามีการแทรก/ลบ/สลับคอลัมน์ในชีต
   แก้โดยให้ `Code.gs` ค้นหาคอลัมน์ "ช่องทางการลงขาย 1", "ช่องทางการลงขาย 2", "ราคาขาย",
   และ "คงเหลือ" **จากชื่อหัวตาราง** แทน (เหมือนที่ทำกับ `MovementLog`/`ListingLog` อยู่แล้ว)
   ทำให้ทนทานต่อการสลับคอลัมน์ในอนาคต

**⚠️ ขั้นตอนสำคัญที่มักถูกลืม:** หลังวางโค้ด `Code.gs` ใหม่ทับของเดิมใน Apps Script แล้ว
ต้องกด **Deploy > Manage deployments > (ไอคอนดินสอ) > Version: New version > Deploy**
ทุกครั้ง ไม่งั้นลิงก์ `/exec` เดิมจะยังรันโค้ดเวอร์ชันเก่าอยู่ และปัญหาข้างต้นจะดูเหมือนไม่หาย
ไปแม้จะแก้โค้ดแล้ว


โปรเจกต์นี้มี 2 ส่วน:

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | หน้าเว็บแอป (frontend) — ทดสอบใน VS Code ได้ทันที |
| `Code.gs` | โค้ด Google Apps Script (backend) — วางในสคริปต์ที่ผูกกับ Google Sheet |

## 1. ทดสอบ UI ก่อนใน VS Code (ยังไม่ต้องเชื่อมชีตจริง)

1. เปิดโฟลเดอร์นี้ใน VS Code
2. ติดตั้ง extension **Live Server** (ถ้ายังไม่มี)
3. คลิกขวาที่ `index.html` > **Open with Live Server**
4. ตอนนี้แอปจะรันด้วย **mock data** (มีตัวอย่างสินค้า 8 รายการจากชีตจริงให้ลองกด "บันทึกเคลื่อนไหว" / "บันทึกลงขาย" ได้เลย — ข้อมูลจะหายเมื่อรีเฟรชหน้า เพราะยังไม่ได้ต่อกับชีตจริง)

ถ้าอยากปรับดีไซน์ ตาราง หรือฟอร์ม แก้ที่ `index.html` ได้ตรงๆ — ทุกอย่างอยู่ไฟล์เดียว (HTML + CSS + JS)

## 2. เชื่อมกับ Google Sheet จริง ผ่าน Apps Script

### ขั้นตอน
1. เปิดชีต **"สินค้า Dead Stock 2569 ต้องผลักดัน"**
2. เมนู **Extensions (ส่วนขยาย) > Apps Script**
3. ลบโค้ดตัวอย่าง (`function myFunction() {}`) แล้ว **วางโค้ดทั้งหมดจาก `Code.gs`**
4. **สำคัญ:** แก้บรรทัด `const SHEET_NAME = 'Sheet1';` ให้ตรงกับชื่อแท็บจริงของคุณ (ดูชื่อแท็บที่ด้านล่างของ Google Sheet)
5. ตรวจสอบว่าตำแหน่งคอลัมน์ตรงกับของจริง (ในโค้ดตั้งไว้ตาม A–U ที่เห็นในไฟล์ต้นฉบับ: รหัสสินค้า, ชื่อสินค้า, หน่วยนับ, สถานะเฝ้าระวัง, จำนวนคงค้าง, เดือน ม.ค.–ธ.ค. (F–Q), คงเหลือ (R), ช่องทางลงขาย FB (S), ช่องทางลงขาย Shopee (T), ราคาขาย (U)) — ถ้าชีตจริงเรียงคอลัมน์ต่างจากนี้ ให้แก้ที่ตัวแปร `COLS` ด้านบนของไฟล์
6. กด **Deploy > New deployment**
   - Select type: **Web app**
   - Execute as: **Me**
   - Who has access: **Anyone** (หรือจำกัดเฉพาะคนในองค์กรถ้าต้องการ)
7. กด **Deploy** แล้วอนุญาตสิทธิ์การเข้าถึง (Authorize access) ตามที่ระบบขอ
8. คัดลอกลิงก์ **Web app URL** (จะลงท้ายด้วย `/exec`)

### เชื่อมกับหน้าเว็บ
เปิด `index.html` แล้วแก้บรรทัดนี้:

```js
const API_URL = ""; // เดิม
```

เป็น

```js
const API_URL = "https://script.google.com/macros/s/xxxxxxxxxxxxxxxxxxx/exec";
```

บันทึกไฟล์ แล้วรีเฟรชหน้าเว็บ — แถบสีเหลือง "โหมดทดสอบ" จะหายไป และข้อมูลทั้งหมดจะดึงจากชีตจริง

## 3. การทำงานของระบบ (อัปเดต: หน้าเว็บเป็นการแสดงผลอย่างเดียว)

หน้าเว็บ (`index.html`) เป็น **แดชบอร์ดแสดงผลอย่างเดียว** สำหรับนำเสนอในที่ประชุม ไม่มีปุ่มบันทึกเคลื่อนไหว/ลงขายแล้ว — การอัปเดตข้อมูล (เคลื่อนไหวสต็อก, วันที่ลงขาย) ให้ทำผ่าน **AppSheet** ตามปกติ หน้าเว็บจะดึงข้อมูลล่าสุดจากชีต (ผ่าน Apps Script) มาแสดงเท่านั้น

หน้าเว็บจะดึงข้อมูลแล้วแยกคำนวณเป็น 2 หมวดหมู่โดยอัตโนมัติ:
- **Dead Stock** — ถ้าค่าในคอลัมน์ "สถานะ" (คอลัมน์ D) มีคำว่า `Dead` อยู่ในข้อความ
- **สินค้าทั่วไป** — สินค้าที่เหลือทั้งหมด (สถานะว่าง หรือไม่มีคำว่า Dead)

> ⚠️ ถ้าคอลัมน์สถานะจริงในชีตของคุณใช้คำอื่น (เช่น "ค้างสต็อก" แทน "Dead Stock") ให้แก้เงื่อนไขในฟังก์ชัน `categoryOf()` ในไฟล์ `index.html` ให้ตรงกับคำที่ใช้จริง

**แหล่งข้อมูลของแต่ละส่วน (อัปเดตล่าสุด — รอบที่ 2):**

| ส่วนในเว็บ | อ้างอิงจาก |
|---|---|
| ตารางรายการสินค้า, มูลค่าคงเหลือ, กราฟแนวโน้มรายเดือน | ชีตหลัก แท็บ `ENGSPTอะไหล่ไหม่` — คอลัมน์เดือน (ม.ค.–ธ.ค.) ต่อสินค้า |
| คงเหลือ (ยอด + มูลค่า) | คอลัมน์ **"คงเหลือ"** ในชีตหลัก |
| ประวัติการเคลื่อนไหว | สร้างจากคอลัมน์เดือน (ม.ค.–ธ.ค.) ของสินค้าแต่ละตัวในชีตหลัก (เดือนที่มียอด ≠ 0) |
| ประวัติการลงขาย | สร้างจากคอลัมน์ **"ช่องทางการลงขาย 1"** (FB) และ **"ช่องทางการลงขาย 2"** (Shopee) ในชีตหลัก โดยแยกวันที่ออกจากข้อความในเซลล์ |
| ลงขายแล้วบน Facebook | คอลัมน์ **"ช่องทางการลงขาย 1"** ในชีตหลัก |
| ลงขายแล้วบน Shopee | คอลัมน์ **"ช่องทางการลงขาย 2"** ในชีตหลัก |
| ราคา/หน่วย | คอลัมน์ **"ราคาขาย"** ในชีตหลัก |

`Code.gs` จะ**ค้นหาคอลัมน์ในชีตหลักจากชื่อหัวตาราง** (ไม่ใช่นับตำแหน่งคอลัมน์ตายตัว: รหัสสินค้า,
ชื่อสินค้า, หน่วยนับ, สถานะ, จำนวนคงค้าง, คงเหลือ, ช่องทางการลงขาย 1/2, ราคาขาย และเดือน
ม.ค.–ธ.ค.) เพื่อให้ทนทานต่อการแทรก/ลบ/สลับคอลัมน์ในอนาคต ถ้าเปิดใช้งานจริงแล้วยังดึงข้อมูลผิด
ให้ส่งชื่อหัวคอลัมน์ (แถว 1–2) ของชีตหลักมาตรวจสอบได้

แท็บ `MovementLog`/`ListingLog` ไม่ได้ถูกใช้อ่านข้อมูลแล้ว (ฟังก์ชัน `addMovement` / `addListing`
ที่เคยเขียนลง 2 แท็บนี้ยังอยู่ในไฟล์เผื่อใช้งานในอนาคต แต่หน้าเว็บปัจจุบันไม่ได้เรียกใช้ เพราะการ
บันทึกข้อมูลทั้งหมดย้ายไปทำที่ AppSheet บนชีตหลักโดยตรง)

## 4. ข้อควรระวัง

- ถ้าเปลี่ยนโค้ดใน Apps Script หลัง deploy ไปแล้ว ต้องกด **Deploy > Manage deployments > แก้ไข (ไอคอนดินสอ) > Version: New version > Deploy** ใหม่ทุกครั้ง ไม่งั้นลิงก์เดิมจะยังใช้โค้ดเก่า
- ฟิลด์ `SHEET_NAME` และตำแหน่งคอลัมน์ใน `COLS` ต้อง**ตรงกับชีตจริงเป๊ะ** ไม่งั้นจะบันทึกผิดตำแหน่ง แนะนำให้ลองกับชีตสำเนา (Make a copy) ก่อนใช้กับชีตจริง
